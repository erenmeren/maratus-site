The path of a request

api.maratus.co

  1. Your till sends a link

    The POS, CRM, loyalty or booking system makes one request with a device ID and a URL. If it knows the register and not the device, it sends the register number instead.

    POST /v1/devices/DEVICE_ID/trigger
"url": "https://example.com/receipt/8812"

  2. The API checks the key and the device

    A device that is paused, or has not checked in for 15 minutes, gets 409 device_offline and nothing is shown. Otherwise the command is published to the device. 202 means published, which is a moment before the code is on screen.

    202 Accepted
{ "id": "cmd_4Qp0dN7hZk2bWm9xYc1aE",
  "status": "queued" }

  3. The device shows the code

    An online device typically shows it within a few seconds, then goes back to its idle screen after your organization’s QR timeout. A command expires 60 seconds after it is accepted, so nothing appears late.

    "action": "show_qr"

  4. The phone opens your own link

    The customer’s browser goes straight to your URL. You host the page, so what it shows, and counting who opened it, stays with you. Maratus can’t tell whether a customer scanned.

    GET /receipt/8812
Host: example.com

What you can call

Nine calls, all under https://api.maratus.co/v1.

Trigger

Show a code now. Scope devices:trigger. Idempotency-Key is required: use a new value for each trigger and the same value when you retry it.

  • POST/devices/{deviceId}/triggerTrigger a device
  • POST/registers/{registerNumber}/triggerTrigger a device by register number

Pin

The code an idle device shows between triggers. Scope devices:pin.

  • PUT/devices/{deviceId}/pinSet a device’s pin
  • DELETE/devices/{deviceId}/pinReset a device’s pin to inherit
  • PUT/stores/{storeId}/pinSet a store’s pin
  • DELETE/stores/{storeId}/pinReset a store’s pin to inherit
  • PUT/org/pinSet the organization pin
  • DELETE/org/pinClear the organization pin

Usage

Triggers your devices acknowledged in the current UTC calendar month. Scope usage:read.

  • GET/usageGet this month’s trigger count

The nearest pin wins

A device with its own pin shows it. A device set to inherit follows its store, and a store set to inherit follows the organization. A level set to none shows no pinned code.

Copy it, then change two values

Put in your key and a device ID. Both are in the console at console.maratus.co: keys under API, the device ID on the device’s own page. The full key is shown once, when it is created.

curl

curl -X POST https://api.maratus.co/v1/devices/DEVICE_ID/trigger \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: $(uuidgen)" \
  -d '{
    "action": "show_qr",
    "payload": { "url": "https://example.com/receipt/8812" }
  }'

JavaScript

const url = "https://api.maratus.co/v1/devices/DEVICE_ID/trigger";
const res = await fetch(url, {
  method: "POST",
  headers: {
    "Authorization": "Bearer YOUR_API_KEY",
    "Content-Type": "application/json",
    "Idempotency-Key": crypto.randomUUID(),
  },
  body: JSON.stringify({
    action: "show_qr",
    payload: { url: "https://example.com/receipt/8812" },
  }),
});

const body = await res.json();
if (res.status === 202) console.log(body.id);
else console.error(body.error.code);

Python

import uuid
import requests

res = requests.post(
    "https://api.maratus.co/v1/devices/DEVICE_ID/trigger",
    headers={
        "Authorization": "Bearer YOUR_API_KEY",
        "Idempotency-Key": str(uuid.uuid4()),
    },
    json={
        "action": "show_qr",
        "payload": {"url": "https://example.com/receipt/8812"},
    },
)

body = res.json()
print(body["id"] if res.status_code == 202 else body["error"]["code"])

Auth and errors

Every request needs an API key, sent as a bearer token.

Authorization: Bearer YOUR_API_KEY

Errors share one JSON shape. Branch on code; message is for people and may change. An unexpected fault can return a 500 without that shape: treat it like internal_error.

Success is 202 for a trigger and 200 for pin and usage calls.
